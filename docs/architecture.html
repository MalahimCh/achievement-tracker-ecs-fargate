SYSTEM ARCHITECTURE

Achievement Tracker on AWS — ECS Fargate, no ALB

Two React frontends (frontend-add, frontend-list), a FastAPI backend and PostgreSQL, all running as ECS Fargate tasks. A single Nginx Fargate task in a public subnet is the only internet-facing resource — it terminates :80 on its own public IP and does path-based routing (/app1/, /app2/, /api/) itself. No Application Load Balancer, no target groups. Everything else lives in private subnets and talks over ECS Service Connect (namespace achievement).

Request flow — what actually happens when a browser hits each path

GET /app1/
Loading the Add-Achievement page — static HTML/JS/CSS, no database involved.
  1. Browser sends GET /app1/ to 13.201.115.142:80.
  2. Ingress hits achievement-alb-sg (80 from 0.0.0.0/0) → reaches the nginx task.
  3. Main nginx matches location /app1/ → proxy_pass http://frontend_add/, resolved via Service Connect to the frontend-add task.
  4. Traffic to frontend-add checked against achievement-frontend-sg (80 from alb-sg).
  5. frontend-add's own nginx matches location / → try_files → serves index.html built with Vite base:"/app1/", so asset URLs are already /app1/assets/....
  6. Browser then requests those assets — same route, same two hops, served straight from the frontend-add container's static files.
POST /app1/api/achievements
The React app calling its API — this is the double-proxy hop, the important one.
  1. App.jsx calls axios.post(`/app1/api/achievements`) — browser sends it to 13.201.115.142:80.
  2. Main nginx still matches the broad location /app1/ prefix (it has no more specific /app1/api rule) → forwards the whole path to frontend-add:80.
  3. Inside the frontend-add container, its own nginx now sees /api/achievements and matches its location /api/ → proxy_pass http://backend:8000/.
  4. Service Connect resolves backend to the backend task's private IP; SG check: achievement-backend-sg allows 8000 from achievement-frontend-sg.
  5. FastAPI backend handles the POST, writes to Postgres via DATABASE_URL=...@db:5432/achievements — Service Connect alias db, SG achievement-rds-sg allows 5432 from backend-sg.
  6. Response flows straight back up the same two hops (backend → frontend-add nginx → main nginx → browser).
GET /api/achievements
Direct top-level API call (what the curl verification test used) — bypasses both frontends entirely.
  1. Client sends GET /api/achievements straight to 13.201.115.142:80.
  2. Main nginx matches its own location /api/ block → proxy_pass http://backend/ directly — frontend-add and frontend-list are never touched.
  3. Service Connect alias backend:8000, SG check: achievement-backend-sg allows 8000 from achievement-alb-sg (this is the rule that exists specifically for this direct path).
  4. Backend queries Postgres over db:5432, returns JSON (this is the call that returned the achievement record with id 1 during verification).
  5. Response returns through nginx to the client, tagged Server: nginx/1.31.3.
This route exists as a convenience/health-check path; the React apps only ever call /app1/api/... or /app2/api/..., which go through step 2 of the flow above (the double-hop).

Why it's built this way

No ALB, by requirement

Routing that would normally be an ALB listener + path-based rules + target groups is done entirely by nginx's own location blocks. The nginx ECS service shows "Load balancing (0)" — it isn't attached to any ELB resource at all. The public IP on the Fargate task is the only entry point.

Public vs. private split

Only the nginx task sits in a public subnet with a public IP and an internet-route security group. Frontends, backend, and Postgres are all in private subnets with no public IP — they can only be reached from inside the VPC, and only over the specific ports their upstream neighbor needs.

Service Connect over Compose DNS

Docker Compose's automatic service-name DNS (backend, db) doesn't exist in ECS by default, so the achievement Service Connect namespace recreates the same short hostnames, letting the exact same nginx.conf and DATABASE_URL from the Compose lab work unchanged on Fargate.
